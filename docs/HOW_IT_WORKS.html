01

What the Project Does

SEB Bot is a Windows automation utility built around special tags written in focused text. The application continuously reads the active text context, detects supported tags, and performs the corresponding action.

Depending on the tag, the action can involve text manipulation, clipboard operations, keyboard automation, an AI request, a screenshot, or a Gemini chat session.

The tag system is the main interface between the user and the application. Tags are intentionally short and can be embedded directly in supported text.

03

scripts/install.bat — Installation

The installation script prepares the Python environment and installs the packages listed in requirements.txt.

The intended setup path is to run the supplied scripts/install.bat rather than manually installing individual dependencies.

Run installation once after obtaining the project, or again after dependency requirements have changed.
04

scripts/start.bat — Launching the Application

The start script launches the application's Python entry point. Keeping the launch command in a batch file makes starting the project consistent without manually typing the Python command each time.

The application then enters its main processing loop and waits for supported tags.

05

settings.json + config.py

Runtime configuration is stored in settings.json. The configuration layer reads those values and makes them available to the rest of the application.

Typical configuration responsibilities

  • AI provider configuration.
  • API credentials or provider-specific settings.
  • Model selection.
  • Application behavior controlled through configuration values.
Keep private credentials inside the local configuration file and do not commit secrets to the repository.

settings.example.json provides a template for creating the local settings file.

detector.py — Tag Detection

The detector maintains the list of recognized tags and determines whether a tag should be processed.

It also handles repeatability rules. Some tags are designed to be used repeatedly, while ordinary tags are protected from being triggered continuously by the same unchanged input.

Repeatable actions

Actions such as screenshots, copying, and chat-related commands can be intentionally repeatable. This allows the same type of command to be used again without requiring unrelated text changes.

The repeatability logic is important for screenshot workflows because multiple screenshots can be added during one active chat session.
09

ai_provider.py — AI Provider Layer

The AI provider layer isolates AI communication from the rest of the application. Tag handlers request an AI operation without needing to implement provider-specific API details themselves.

Standard AI requests

Regular request tags can send text-based prompts to the configured AI provider and return the resulting response to the UI.

Gemini chat

Gemini chat is persistent for the lifetime of the active chat session. This allows multiple messages to share the same conversation context.

Screenshot-aware Gemini chat

The screenshot-aware workflow adds visual context to the conversation. @@SSTOCHAT@@ creates a chat using a newly captured screenshot as initial visual context.

@@SSTOSS@@ captures another screenshot and adds it to the already-open screenshot-aware Gemini chat.

Screenshots are treated as visual context for the AI conversation. The chat response behavior remains text-based and uses plain formatting.

tag_handlers.py — Tag Handlers

Once a tag is detected, tag_handlers.py maps it to the corresponding operation.

The handler layer is where individual commands are connected to the reader, clipboard, keyboard, screenshot, AI, and UI functionality.

Screenshot chat handlers

SSTOCHAT

Captures a screenshot and opens a Gemini chat with that screenshot supplied as the initial visual context.

SSTOSS

Captures another screenshot and sends it to the currently active screenshot-aware Gemini chat.

12

keyboard_input.py — Keyboard Automation

Keyboard automation is isolated in its own module so handlers can request keyboard actions without directly managing low-level input behavior.

This separation keeps tag handling focused on what an action should do, while the keyboard module handles how keyboard input is generated.

14

Complete Tag Reference

Tags use the format @@TAG@@ or, for commands that require text, @@TAG: content@@.

Tag Purpose
@@ASK: question@@ Send a question to the configured AI provider.
@@SOLVE: task@@ Ask the AI provider to solve or work through a task.
@@FIX: instruction@@ Ask the AI provider to fix or modify supplied content according to the instruction.
@@COPY: text@@ Copy the supplied text to the clipboard.
@@COPYABOVE@@ Copy the relevant text above the tag.
@@COPYALL@@ Copy the relevant complete text/context.
@@SCREENSHOT@@ Capture a screenshot and save it locally.
@@ASKALL: question@@ Send a question together with the relevant full context.
@@SOLVEALL@@ Ask the AI to solve using the relevant full context.
@@PASTE@@ Perform the supported paste operation.
@@CHAT@@ Open or use the Gemini chat interface.
@@CLIPBOARD@@ Use clipboard content as supported by the handler.
@@SSTOCHAT@@ Take a screenshot and open a Gemini chat with that screenshot as the initial visual context.
@@SSTOSS@@ Take another screenshot and add it to the already-open screenshot-aware Gemini chat.
The screenshot-aware tags are different from the standalone @@SCREENSHOT@@ tag. @@SCREENSHOT@@ only performs the screenshot action, while @@SSTOCHAT@@ connects the captured screenshot directly to a Gemini chat session.

End-to-End Examples

Text request

@@ASK: Explain this concept@@

The detector recognizes the tag, the handler extracts the request, the AI provider processes it, and the UI displays the response.

Screenshot only

@@SCREENSHOT@@

The screenshot handler captures the current screen and saves the image according to the application's screenshot workflow.

Start a screenshot-aware Gemini chat

@@SSTOCHAT@@

The application captures a screenshot and starts a Gemini chat with the captured image included as visual context.

Add another screenshot to that chat

@@SSTOSS@@

The application captures another screenshot and sends it to the existing screenshot-aware chat, allowing the conversation to continue with additional visual context.

A useful mental model is: @@SSTOCHAT@@ starts the visual conversation; @@SSTOSS@@ continues adding visual context to it.
16

Common Problems and Notes

AI requests do not work

Check that the required provider configuration exists in settings.json and that the selected provider/model is configured correctly.

Tags are not detected

Check that the tag matches the supported syntax exactly. The detector recognizes the application's defined tag names and delimiters.

Gemini chat does not continue

Chat commands depend on the active chat state maintained by the UI and AI provider layers.

@@SSTOSS@@ does not have a chat to update

@@SSTOSS@@ is intended to add a screenshot to an existing screenshot-aware Gemini chat. Start one with @@SSTOCHAT@@ first.

Multiple screenshots

The screenshot-aware workflow supports adding additional screenshots to the active conversation. Each @@SSTOSS@@ action captures another image rather than replacing the previous screenshot context.

Configuration files

Do not place API keys or other private credentials into documentation, source examples, or public repository files.
